## §1 جرد الشاشات + بوابة الاختيار

1. **اعثر على كل شاشة:** ابحث في `lib/` عن الراوتر والنقاط اللي بتفتح شاشات:
   - `GoRoute(` / `path:` / `routes:` (go_router)
   - `Navigator.push` / `MaterialPageRoute` (تنقّل يدوي)
   - الـtabs والدرج (drawer) — وصل كل شاشة لطريقة الوصول لها
2. **اعمل جدول اللقطات قبل ما تبدأ** واحفظه في `SCREENSHOTS_RUNBOOK.md` بتاع المشروع:

   | اسم الملف | الشاشة | إزاي أوصّل لها | البيانات اللي لازم تبان |
   |---|---|---|---|
   | `NN-name.png` | اسم الشاشة | بلاطة/درج/تاب/رابط مباشر | صفوف محددة، مبالغ، تواريخ، شارات |

3. **فولدر العرض الموحد — مكان واحد لكل المواد:** اعمل `assets/portfolio/`
   وحط جواه كل مواد العرض: `shots/` (اللقطات) · `app_icon/` (الأيقونات بكل
   أبعادها) · `PORTFOLIO.md` (التعريفية) — كده يترفع الفولدر كله على أي منصة
   ويفهم زائر الريبو كل حاجة من مكان واحد. **متسجّلهوش في pubspec assets**

4. **بوابة الاختيار (السؤال الوحيد):** «كل السكرينات ولا محددة؟» →
   سجّل القائمة النهائية، وبعدها امشي من غير ما ترجع تسأل.

## §2 البيانات — الأساس اللي كل حاجة واقفة عليه

- **قاعدة أولى:** مفيش لقطة لشاشة فاضية ولا فيها بيانات اختبار
  (`test` / `123` / `aaa` / `demo`). لو الشاشة مالهاش داتا → ازرعها الأول.
- **سكريبت واحد idempotent** المستخدم يشغّله بنفسه في SQL Editor
  (الـAI معندوش service key — قراءة REST بالـpublishable key بس):
  حذف بأيد ثابتة (`DELETE ... WHERE id IN (...)` أو بـ`user_id` ثابت)
  + إدراج بنفس الـids → أي إعادة تشغيل تانية مبتكسرش حاجة.
- **كل التواريخ نسبية لـ`CURRENT_DATE`** — الأجندة/النشاط لازم يفضلوا معمّرين
  مهما اتسحب التصوير بعد أسبوع:
  `CURRENT_DATE - interval '3 days'` · `CURRENT_DATE` · `CURRENT_DATE + interval '2 days'`.
- **تنوّع الحالات عمدًا** (عشان كل لقطة تحكي قصة):
  نفس اليوم = جلسات + أعمال إدارية معًا · قضايا بدفعات ونِسب إنجاز ·
  أكتر من محامي وأرصدة مختلفة · دخل ومصروف · قضايا في تصنيفات متفاوتة.
- **تحقّق بالـREST قبل التصوير** — عدّادات + قيم حرجة (مثال Supabase):

  ```js
  const r = await fetch('https://PROJECT.supabase.co/rest/v1/TABLE?select=id,key_col&limit=5', {
    headers: {
      apikey: 'sb_publishable_XXX',
      Authorization: 'Bearer sb_publishable_XXX',
    },
  });
  console.log(await r.json());
  ```

- **بعد ما يقول «شغّلت»** → كرّر الـprobe: العدادات + القيم الحرجة
  (مثلاً: قيد النهارده موجود · محامي كل قضية = المتوقّع · مجموع الخزينة) —
  **متبدأش التصوير من غير تأكيد الداتا.**

## §3 البناء release فقط — مفيش نقاش

- **ليه:** البناء العادي (`flutter run`) برسم **badge أسود** في الركن فيه أرقام
  القياس (`ref / screen / scale`) — اسمه `DebugMetricsOverlay` — وكمان شرائط
  overflow صفراء/سوداء. الحاجتين دول يقتلوا صورة بورتفليو.

  ```powershell
  flutter build apk --release
  adb install -r build\app\outputs\flutter-apk\app-release.apk
  ```

- **شاشة اللوجين = تسجيل خروج فعلي، فممنوع تسجيل الخروج بدون إذن صريح.**
  كتلة الراوتر بتطرد المستخدم المسجّل من `/login` للرئيسية — يعني **مفيش طريقة
  تاني تصوّر بيها اللوجين غير الخروج من الحساب.** ولما المستخدم يصرّح:
  1. الدرج → «تسجيل خروج» (غالبًا بدون dialog تأكيد) → التطبيق يروح للوجين.
  2. صوّر اللوجين، ولو فيه لينك تواصل/مستخدم جديد جواه افتحه وصوّره كمان.
  3. رجّع التطبيق على شاشة اللوجين، **وأبلغه صراحة:** «التطبيق بقى مسجّل خروج —
     سجّل دخول بنفسك» — ومتلعبش في حساباته أبدًا.

## §4 التصوير على الإيموليتر

- **التقاط (آمن ترميزيًا على PowerShell):**

  ```powershell
  cmd /c "adb exec-out screencap -p > assets\portfolio\shots\NN-name.png"
  ```

  التحويل المباشر (`adb ... > file.png`) بيكسر الـPNG في PowerShell — دايمًا `cmd /c`.

- **إكتشاف الإحداثيات — الدورة:** صوّر مؤقت (`_tmp-*.png`) → **اقرأ الصورة** →
  احسب الإحداثيات (720x1280 = إحداثيات البكسلات الفعلية) → اضغط → صوّر واقرأ النتيجة.
  متحرّكش في الظلام أبدًا.

- **قواعد التنقّل (من خبرة حقيقية):**

  | الحركة | النتيجة |
  |---|---|
  | سحب من **وسط** الشاشة | سكرول ✓ |
  | سحب من قرب **الحافة** (~60px) | **back gesture** يطيّي الصفحة ويقفلك شجرة التنقّل ✗ |
  | `adb shell input keyevent 4` | رجوع آمن (بديل السحب) |
  | `adb shell monkey -p PKG -c android.intent.category.LAUNCHER 1` | يرجّع التطبيق فورًا لو طلع للاستديو |
  | `adb shell am force-stop PKG` + relaunch | حالة نضيفة (لما الشاشة الحالية تبقى فاضية/مريبة) |

- **وقت الانتظار:** الشاشات اللي بتسحب sums/charts من الشبكة بترسم بعد ما يختفي
  الـ`CircularProgressIndicator` — **تصوير بدري = أصفار في المبالغ** (حصل فعلًا:
  «المحصل 0» بدل 15000). استنى 2 ثانية للتنقّل العادي و4-8 ثواني للشاشات الثقيلة،
  وافحص اللقطة قبل القبول.

## §5 حلقة التحقق من كل لقطة — أهم قسم في الملف

> **القاعدة الذهبية:** كل PNG لازم **يتقرأ بالعين** قبل ما يتقبل.
> مفيش لقطة بتتسجّل في القائمة من غير ما تكون اتفحصت.

1. **افتح الصورة واقرأها:** في إيه؟ الصفوف كاملة؟ التواريخ منطقية؟ الشارات ظاهرة؟
2. **قبل أي استنتاج من نص صغير: قصّ + كبّبّت 4-8x** (الأرقام العربية الصغيرة
   بتتخدع في الرؤية العادية):

   ```powershell
   Add-Type -AssemblyName System.Drawing
   function CropZoom($src,$out,$rx,$ry,$rw,$rh,$z){
     $img=[System.Drawing.Image]::FromFile($src)
     $bmp=New-Object System.Drawing.Bitmap($img)
     $rect=New-Object System.Drawing.Rectangle($rx,$ry,$rw,$rh)
     $crop=$bmp.Clone($rect,$bmp.PixelFormat)
     $big=New-Object System.Drawing.Bitmap($crop,($rw*$z),($rh*$z))
     $g=[System.Drawing.Graphics]::FromImage($big)
     $g.InterpolationMode='NearestNeighbor'
     $g.DrawImage($crop,0,0,($rw*$z),($rh*$z))
     $g.Dispose(); $big.Save($out,[System.Drawing.Imaging.ImageFormat]::Png)
     $crop.Dispose(); $big.Dispose(); $bmp.Dispose(); $img.Dispose()
   }
   CropZoom 'assets\portfolio\shots\16.png' 'assets\portfolio\shots\_tmp-z.png' 380 595 300 70 8   # x y w h zoom
   ```

3. **تشيك ليستة العيوب البصرية** — كل عيب منها حصل فعلًا:

   | العيب في الصورة | السبب المرجح في الكود |
   |---|---|
   | badge أسود بأرقام في الركن | اتبنى **debug** مش release |
   | نص مش ظاهر خالص (خانة فاضية) | مفيش `color` صريح في الـ`TextStyle` → أبيض على أبيض |
   | محدّد معلّق لوحده (نقطة `•` من غير الكلام بعدها) | `Row` فيها `Text` اختياري فاضي + فاصل ثابت |
   | نص **ملزوق** بنص تاني | مفيش `SizedBox` gap بين النص والمبلغ |
   | مبالغ/عدادات = صفر | التصوير اتعمل وأنت في نص التحميل — أعد بأنتظار أطول |
   | زرار عائم (FAB) مغطّي على بيانات مهمة | سكرول بسيط من وسط الشاشة أو قبول لو المعلومة ظاهرة |
   | ترتيب زمني معكوس | الـsort بيقرأ عمود غلط (مثلاً `created_at` مش تاريخ الحدث نفسه) |

4. **أي عيب سببه الكود → صلّحه + build جديد + أعد تصوير اللقطة دي.**
   مفيش تسليم لقطة فيها عيب معروف — الصور دي للبورتفليو، مش تقرير أخطاء.

## §7 بوابة التسليم (Delivery Gate) — مفيش تسليم من غيرها

1. **كل** لقطة في القائمة اتقريت واتأكدت منها (§5) ✓
2. جدول التغطية كامل: كل route = لقطة أو سبب صريح (§6)
3. `flutter analyze` = البازلاين بتاع المشروع (0 errors) +
   `flutter test` = نفس النتيجة قبل التغييرات (فشل قديم معروف = سليم)
4. امسح مؤقتات التحقق: `Remove-Item assets\portfolio\shots\_tmp-*.png`
5. **زامن ملفات التعريفية:** الرووت هو المصدر → انسخها جوّه الفولدر:
   `Copy-Item README.md, PORTFOLIO.md assets\portfolio\ -Force`
6. **التقرير النهائي:** جدول اللقطات (اسم · اللي اتغيّر) + الملفات المغيّرة +
   طريقة التحقق — بالعربي وبشكل مختصر.

## §8 كتلة أوامر جاهزة (PowerShell + adb)

```powershell

flutter build apk --release
adb install -r build\app\outputs\flutter-apk\app-release.apk

# 4) سكرول آمن من وسط الشاشة
adb shell input swipe 360 900 360 520 350

# 5) رجوع آمن (مش سحب حافة!)

# 6) إنقاذ سريع لو التطبيق طلع للاستديو
adb shell monkey -p PKG -c android.intent.category.LAUNCHER 1 | Out-Null
```

## §9 ملاحظات تجهيز الملفات للمنصة (اللي بعد التصوير)

- `assets/portfolio/shots/` كلها PNG بدقّة عالية — سيبها بالحجم اللي الإيموليتر أخرجها بيه
  (720x1280 مثلاً) ومتعملهاش downscale لحد ما ترفعها.
- **ملفات التعريفية — المكانين إجباريين:** كل ملف تعريفي (`README.md` ·
  `PORTFOLIO.md` · وغيرهم) يبقى **في جذر المشروع** (المنصات بتكشف ملفات الرووت)
  **ونسخة منه جوّه `assets/portfolio/`** عشان الفولدر يرفع لوحده وهو كامل
  (شرح + صور + أيقونة). **الرووت هو المصدر** وأي تعديل يتنسخ للجوّه
  (خطوة 5 في §7). المحتوى على الأقل:
  - `README.md` → وصف المشروع + جدول التقنيات (دخول/بيانات/تقنية) +
    لينك لمواد العرض في `assets/portfolio/` + طريقة التشغيل السريعة +
    فهرس ملفات التوثيق.
  - `PORTFOLIO.md` → الوصف التفصيلي: الميزات · جدول اللقطات (كل شاشة بالاسم) ·
    الأصول المُستخرجة (أيقونة بكل الأحجام) · التشغيل من الصفر (seed + build).
- **رابط الريبو (لو موجود):** جيبه من `git remote get-url origin` وحطه في
  `README.md` (جوّه جدول التقنيات) + `PORTFOLIO.md` — **م تخترعش رابط**:
  لو مفيش remote يبقى سيبه فاضي وقول المستخدم يضيفه وقت الرفع.
- **ملف الران‑بوك الخاص بالمشروع** (`SCREENSHOTS_RUNBOOK.md`): خلّيه دايمًا مطابق
  للحالة الفعلية (أسماء اللقطات + إحداثيات التنقّل + أيام الداتا) —
  أي تعديل على التصوير يتسجّل فيه في نفس الجلسة.

## §10 استخراج الأيقونة والصور (assets extraction)

> **المشغِّل:** «استخرج أيقونة البرنامج» · «عايز الأيقونة بكل الأحجام» ·
> «استخرج الصور» · «زي ما اتفقنا» (لما يقصد الاستخراج) — ساعتها نفّذ §10 ده
> في المشروع الحالي وسجّل النتيجة.

1. **لاقي كل المصادر:**
   - أندرويد: `android/app/src/main/res/mipmap-*/ic_launcher.png` (٥ أحجام)
   - أندرويد adaptive (لو موجود): `mipmap-anydpi-v26/ic_launcher.xml` — vector
     بيتصبّر لأي حجم بدون فقد
   - iOS: `ios/Runner/Assets.xcassets/AppIcon.appiconset/` (~15 حجم)
   - صور التطبيق داخل `assets/` (Logo/Icon بأسماء متفاوتة)
2. **قيس الأبعاد الحقيقية + افتح كل ملف بالعين** (`System.Drawing` → `Width/Height`)
   — **الفخ:** أي مشروع Flutter جديد أيقونات iOS = **لوجو Flutter الأزرق الافتراضي**،
   مش أيقونة التطبيق. متنسخّهاش للمعرض، و**بلّغ المستخدم** إنها لسه افتراضية.
3. **سمّي كل صورة بأبعادها المقاسة فعليًا** وانسخها لفولدر الأيقونات **جوه فولدر
   العرض الموحد**: `assets/portfolio/app_icon/` — بالصيغة
   `ic_launcher_48x48.png` · `ic_launcher_192x192.png` …
4. **الفولدر ده للعرض/الرفع بس — متسجّلهوش في pubspec assets**
   (تسجيله = يتحمّل جوه الـAPK زيادة على المتجر).
5. **متكبّرش (upscale) في السر:** أقل حجم أصلي هو أقصى جودة حقيقية — لو منصة
   الرفع محتاجة حجم أكبر (512 مثلاً) قول للمستخدم يجيب الأصل عالي الدقة بدل
   ما تزوّد بيانات وتزوّر الجودة.
6. **التقرير:** جدول الملفات (الاسم · الأبعاد · المصدر) + أي مصدر لسه افتراضي
   + الخطوة الجاية المقترحة.

### §10.1 الأيقونة التكيّفية (adaptive icon) — مقاس ثابت مُعتمد

> **المشغِّل:** الأيقونة بتبان **أصغر** من أيقونات جوارها في اللانشر (Gmail/Play)
> · أو عند توليد أيقونة أندرويد من جديد · أو لما المستخدم يقول «عايزها كبيرة زي جوجل».
>

**الليه:** أندرويد ٨+ بيلفّ أيقونة `legacy` (مجرد PNG في `mipmap-*`) جوّه قناع
الـadaptive و**بيصغّرها ≈٧٢٪**، بينما الأيقونة التكيّفية بتتملّى الدايرة. علشان كده
التطبيق بيبان صغير **حتى لو الرسم ممتلئ ١٠٠٪ من مربّعه** — السبب مش في الصورة،
السبب إنها legacy. الملفات المطلوبة تلاتة:

| الملف | الدور |
|---|---|
| `res/mipmap-anydpi-v26/ic_launcher.xml` | بيعرّف الطبقتين (background + foreground) |
| `res/values/ic_launcher_background.xml` | لون الخلفية — **اختره من نفس خلفية الرسم** |
| `res/mipmap-{dpi}/ic_launcher_foreground.png` | الطبقة الأمامية بكل الكثافات |

**الإجراء خطوة بخطوة:**

1. **قِس الهوامش الشفافة وقصّها من المصدر قبل أي حاجة** (متخمّنش): مسح الـalpha على كل
   الحواف يبيّن الهوامش — **غير متساوية عادة** (في مصدر law_office كان فيه ١٧ صف شفاف
   تحت بس). من غير القصّ الشفاف بيتكرّر معاك كشريط بلون الخلفية جوّه قناع اللانشر.
   قصّ الهوامش بيخلّي الرسم full-bleed على الأربع حواف.
2. **المقاس = الافتراضي المثبّت — اتطبّقه على طول من غير سؤال:**
   **`72×72dp` مركزيًا** (حافة القرص = حافة الرسم → صفر خلفية قبل الدهب).
   > **🔒 قرار مثبّت (هشام، ٢٠٢٦-١٠-١٨):** أي أيقونة جديدة في أي مشروع تتحط بالابعاد
   > دي **direct من غير مناقشة**. القناع الدائري بيقصّ زوايا الإطار المربّع المدوّر
   > والركن بيبقى داكن من داخليّة الرسم — ده مقبول ومعروف.
   > `58×58dp` (حفظ الزوايا + حلقة خلفية `7dp`) بقى **أرشيف**، لا يُطبّق غير بطلب
   > صريح بالاسم. `66dp` **اترفض** ولا تعاود. دوّر رقم `72` في كل الجداول تحت.
   > **دائرة / شعار ممتلئ** → `66–72dp` على طول (مفيش زوايا تتنقص).
   > **الرقم يتحدّد من مكان واحد** (`ArtDp` في السكربت) — متغيّرش جداول ولا كود يدوي.
3. **أحجام foreground بالبكسل** = `108dp × density`، والرسم جوّاهم **`72dp × density`**:

   | density | canvas | **الرسم جوّاه** (الافتراضي) | (أرشيف ٥٨) |
   |---|---|---|---|
   | mdpi | 108 | **72** | 58 |
   | hdpi | 162 | **108** | 87 |
   | xhdpi | 216 | **144** | 116 |
   | xxhdpi | 324 | **216** | 174 |
   | xxxhdpi | 432 | **288** | 232 |

4. **سيب `mipmap-*/ic_launcher.png` القديمة مكانها** — دي اللي بياخدوها أجهزة
   أندرويد ٧ وأقدم. مش حذف، ده fallback.
5. **ملفات الـXML بلا BOM** — اكتبها بـ`[System.IO.File]::WriteAllText` +
   `New-Object System.Text.UTF8Encoding($false)`، لأن `Set-Content -Encoding UTF8`
   بيحط BOM وممكن يوقّع `aapt` وقت البناء. تحقّق: أول ٣ بايت = `3C 3F 78`.
6. **`ic_launcher_round.xml` اختياري** — بس لو الـmanifest بيعلن `android:roundIcon`.
7. **فحص رقمي قبل التسليم (وبعد البصرية):** احسب بكسلات `alpha ≤ 8` **جوّه دائرة
   القناع `72/108` بس** في الـforeground المُصدَّر — الهدف `0` (أو رقم فردي تمويه
   حافة). أي رقم تاني = لون الخلفية لسه بيتسرّب → راجع الهوامش/المقاس.

**كود التوليد (PowerShell + GDI+):**

```powershell
# التصغير لازم يتعمل على Format32bppPArgb (premultiplied) وإلا بيتحطّ إطار غامق
# حوالين الحواف، وبعدين نفكّ الـpremultiply قبل حفظ الـPNG.
$layer = New-Object System.Drawing.Bitmap($canvas, $canvas, [System.Drawing.Imaging.PixelFormat]::Format32bppPArgb)
$g = [System.Drawing.Graphics]::FromImage($layer)
$g.InterpolationMode = [System.Drawing.Drawing2D.InterpolationMode]::HighQualityBicubic
$g.SmoothingMode = [System.Drawing.Drawing2D.SmoothingMode]::HighQuality
$g.PixelOffsetMode = [System.Drawing.Drawing2D.PixelOffsetMode]::HighQuality
$g.CompositingMode = [System.Drawing.Drawing2D.CompositingMode]::SourceCopy
$g.Clear([System.Drawing.Color]::Transparent)
$g.DrawImage($src, (New-Object System.Drawing.Rectangle($off, $off, $art, $art)))  # off = (canvas-art)/2
$g.Dispose()
```

```xml
<?xml version="1.0" encoding="utf-8"?>
<adaptive-icon xmlns:android="http://schemas.android.com/apk/res/android">
    <background android:drawable="@color/ic_launcher_background" />
    <foreground android:drawable="@mipmap/ic_launcher_foreground" />
</adaptive-icon>
```
